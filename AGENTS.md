# AGENTS.md — rules for AI agents and contributors

## Read before doing anything

1. [docs/sdd.md](docs/sdd.md) for scope and requirements.
2. [docs/architecture/](docs/architecture/) for how the system fits together.
3. The spec for the feature you are touching, in [specs/](specs/).
4. Relevant ADRs in [docs/adr/](docs/adr/). Do not contradict an accepted ADR without writing a new one that supersedes it.

## Spec-Driven Development workflow

1. **No code without a spec.** If the work has no spec, write `specs/NNN-name/spec.md` from [the template](specs/000-template/spec.md) and stop for review.
2. Write `plan.md` (technical design), then `tasks.md` (ordered checklist).
3. Implement task by task. Tick tasks in `tasks.md` in the same PR.
4. Every acceptance criterion has a test whose name includes its ID, e.g. `test("[001-AC3] closes session when name is clicked")`.
5. When done, set the spec status to `Implemented` and update any architecture doc or ADR the change touched.

## Stack and conventions

- Next.js 16 App Router, TypeScript `strict`, pnpm (run `corepack enable` once). **Cache Components is off** (ADR 0007). Next 16 renamed `middleware.ts` to `proxy.ts`.
- Supabase: schema changes **only** through SQL migrations in `supabase/migrations/` (`supabase migration new <name>`). Never edit the remote DB by hand.
- Regenerate DB types after migrations: `pnpm db:types`. CI fails if the committed types drift.
- **New SQL functions:** `security definer` only when needed, always with `set search_path = ''` and fully qualified names. Revoke `EXECUTE` from `public, anon, authenticated` and grant explicitly, then update the allowlist in `supabase/tests/00_schema_test.sql` ([data-model.md](docs/architecture/data-model.md#function-privileges)).
- **New tables:** enable RLS and grant only what the RLS matrix needs ([data-model.md](docs/architecture/data-model.md#exposure-and-rls-defaults)).
- pgTAP tests run against the seeded local DB. Use your own fixture IDs and codes, and deactivate other members when a test counts track members.
- Business rules that touch many rows (rankings, expected hours) live in SQL functions. Pure date/percentage math is mirrored in `src/lib/attendance/` and unit-tested.
- Validation with Zod at every server boundary (server actions, route handlers). Server actions call `requireAdmin()` / `getAuth()` themselves; never rely on the page or `proxy.ts` alone.
- Server actions return error **codes** (`src/lib/errors.ts`); the UI translates them from `messages/*.json` under `errors`.
- Sign-in is Google only (ADR 0008). Locally, sign in with the dev login (`admin@local.test` / `ana@local.test`).
- All timestamps are `timestamptz`, generated by the DB (`now()`). Display timezone is `America/Sao_Paulo`.
- **No hard-coded UI text.** Every string goes in `messages/pt-BR.json` **and** `messages/en.json` (next-intl, ADR 0006). Use `useTranslations` / `getTranslations`, and format dates and numbers with next-intl formatters, never by hand. Code, identifiers, commits and docs are in **English**.
- Never commit secrets. Add new env vars to `.env.example` and [docs/architecture/ci-cd.md](docs/architecture/ci-cd.md).
- Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`).

## Commands

| Command | What it does |
|---|---|
| `pnpm dev` | Next.js dev server |
| `pnpm lint` / `pnpm typecheck` | ESLint / route typegen + `tsc --noEmit` |
| `pnpm format` / `pnpm format:check` | Prettier write / check |
| `pnpm docs:lint` | markdownlint on all docs |
| `pnpm test` | Vitest unit tests |
| `pnpm test:e2e` | Playwright e2e (needs local Supabase) |
| `pnpm db:start` / `pnpm db:reset` | Start local Supabase / re-apply migrations + seed |
| `pnpm env:local` | Write `.env.local` from the running local Supabase, with the dev login enabled |
| `pnpm db:test` | SQL/pgTAP tests (RLS, RPCs) |
| `pnpm db:types` | Regenerate `src/lib/database.types.ts` |
| `pnpm i18n:check` | Verify every locale has exactly the keys in `messages/pt-BR.json` |

## Definition of done

- Lint, typecheck, unit, DB and e2e tests are green in CI.
- The spec's acceptance criteria are covered by tagged tests.
- Docs and ADRs are updated, and the PR template checklist is complete.
