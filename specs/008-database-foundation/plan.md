# 008 — Technical plan

- Spec: [spec.md](spec.md)

## Overview

Five migrations build the schema bottom-up. All business rules live in SQL functions so the kiosk, admin and member screens share one tested implementation. The attendance math is mirrored in TypeScript for UI-side calculations.

## Changes

| Area | Change |
|---|---|
| `20261010000100_types_and_tables.sql` | Enums, all tables, constraints (one open session, no overlapping sessions/phases, one current season), default settings |
| `20261010000200_helpers_and_rls.sql` | RLS helpers, guard triggers (`members_guard`, `season_phases_within_season`), table grants, RLS policies |
| `20261010000300_attendance_math.sql` | `session_minutes`, `expected_minutes`, `ranking_unchecked`/`ranking`, `my_stats` |
| `20261010000400_rpc.sql` | Kiosk, invites, auto-close, corrections, `set_current_season`, audit trigger |
| `20261010000500_function_privileges.sql` | Revoke-all + explicit allowlist (data-model.md, "Function privileges") |
| `supabase/seed.sql` | Current season with the default FRC phases, demo FTC/mentor phases, 6 demo members (codes 111111–333332) |
| `supabase/tests/*.sql` | pgTAP: schema/privileges, math, kiosk, invites, RLS, auto-close/corrections, rankings/constraints |
| `src/lib/attendance/math.ts` | TypeScript mirror + Vitest worked examples |
| `src/lib/database.types.ts` | Generated by `pnpm db:types` (formatted with Prettier, drift-checked in CI) |

## Risks

- Ranking queries call `member_worked_minutes` per member, which is fine for ~100 members. Revisit with a set-based query if it ever gets slow (NFR-3).
- `kiosk_toggle` locks the member row (`for update`) to serialize double submits.
